## 1. 概览

| 项 | 值 |
|---|---|
| 名称 | Modbus（别名 Modbus TCP / Modbus RTU / Modbus ASCII） |
| 默认端口 | **502/tcp**（Modbus/TCP）；RTU/ASCII 走串行 RS-232/RS-485/RS-422；少数实现用 502/udp |
| 分层 | 应用层协议；TCP/IP 之上（MBAP 封装），或串行链路之上（RTU/ASCII 帧） |
| 通信模型 | 请求/响应（Master-Slave；TCP 语境下常称 Client-Server），非发布订阅 |
| 规范访问 | 公开免费（modbus.org） |
| 认证/加密 | **协议本身无认证、无加密、无完整性保护、无会话** |
| 会话/序号 | 无；仅 MBAP 事务标识符用于匹配响应，不构成安全控制 |
| 单帧上限 | PDU ≤ 253 字节；Modbus/TCP ADU ≤ 260 字节；RTU ADU ≤ 256 字节 |
| 电力相关性 | 中高：配网自动化、电能量计量、辅控系统、老式变电站 RTU 大量使用；主站级保护/远动更常用 IEC 60870-5-104 与 DNP3 |

三种承载（同一 PDU 语义）：

1. **Modbus/TCP**：MBAP 头 + PDU，端口 502/tcp。
2. **Modbus RTU**：从站地址 + PDU + CRC16，二进制串行帧，3.5 字符静默间隔分帧。
3. **Modbus ASCII**：`:` + 十六进制字符 + LRC + CRLF，已基本淘汰。

## 2. Modbus/TCP 帧结构

### 2.1 MBAP 头（7 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | 事务标识符 Transaction Identifier | 客户端生成，服务端原样回填；用于匹配请求/响应 |
| 2 | 2 | 协议标识符 Protocol Identifier | Modbus 恒为 `0x0000`；非 0 一般被丢弃 |
| 4 | 2 | 长度 Length | **其后字节数** = 单元标识符(1) + PDU 长度；取值 2..254 |
| 6 | 1 | 单元标识符 Unit Identifier | 串行链路从站地址语义；直连设备常为 `0x01`/`0xFF`；网关后用于选择下游从站；`0x00` 或 `0xFF` 常用于广播 |

多字节整数一律 **大端（网络序）**。

### 2.2 PDU

```
PDU = 功能码(1 字节) + 数据(N 字节, N ≤ 252)
ADU(MBAP) = MBAP(7) + PDU
```

### 2.3 报文示例（十六进制）

读保持寄存器：单元 1，起始地址 0x0000，数量 10

```
00 01 00 00 00 06 01 03 00 00 00 0A
└─┬─┘ └─┬─┘ └─┬─┘ │ │  └──┬──┘ └─┬─┘
事务=1  协议=0  长度=6 单元 FC=03  起始    数量=10
```

正常响应（10 个寄存器 = 20 字节，长度 = 1+1+1+20 = 23 = 0x17）：

```
00 01 00 00 00 17 01 03 14 <20 字节数据>
```

写单个线圈为 ON（地址 0x00AC）：

```
00 01 00 00 00 06 01 05 00 AC FF 00     # 0xFF00=ON, 0x0000=OFF
```

写多个保持寄存器（起始 0x0000，2 个寄存器，值 0x000A、0x0102）：

```
00 01 00 00 00 0B 01 10 00 00 00 02 04 00 0A 01 02
                        └─┬─┘ └─┬─┘ │  └────┬────┘
                        FC=16 起始  数量=2 字节数=4 + 数据
```

读设备标识（MEI，见 §6）：

```
00 01 00 00 00 05 01 2B 0E 01 00     # FC=0x2B, MEI=0x0E, 读码=01(基本), 对象=0x00
```

异常响应（功能码最高位置 1，此处 0x83 = 0x03|0x80，异常码 0x02）：

```
00 01 00 00 00 03 01 83 02           # 长度=3 = 单元(1)+FC(1)+异常码(1)
```

诊断：强制只听模式（Force Listen Only Mode，子功能 0x0004）：

```
00 01 00 00 00 06 01 08 00 04 00 00
```

## 3. Modbus RTU / ASCII

### 3.1 RTU 帧

```
+--------+--------------+---------------+----------+
| 从站地址 | 功能码        | 数据           | CRC16    |
| 1 字节  | 1 字节        | N 字节         | 2 字节   |
+--------+--------------+---------------+----------+
```

- 从站地址：`0x01`–`0xF7` 为合法单播；`0x00` 为广播（从站不响应）；`0xF8`–`0xFF` 保留。
- CRC16：多项式 0xA001（0x8005 反射），初值 0xFFFF，**低字节先发**（小端在线序）。
- 分帧：帧间静默 ≥ 3.5 个字符时间；帧内字符间隔 > 1.5 字符时间视为帧错误。
- 广播写：主站发地址 0x00，所有从站执行但不应答（对写入类功能码有效）。

### 3.2 RTU 报文示例（CRC 已实测复算）

读保持寄存器：从站 0x11，起始 0x006B，数量 3 —— 与规范示例一致（规范写作 `… 7687`）：

```
11 03 00 6B 00 03 76 87
```

读保持寄存器：从站 0x01，起始 0x0000，数量 1：

```
01 03 00 00 00 01 84 0A
```

响应（寄存器值 0x000A，字节数 2）：

```
01 03 02 00 0A 38 43
```

写单个寄存器（值 0x0064）：

```
01 06 00 00 00 64 88 21
```

异常响应（非法数据地址）：

```
01 83 02 C0 F1
```

### 3.3 ASCII 帧

```
: 0103000000 01 FB CR LF
│ │          │ │  └── LRC = 0xFB（对前 6 字节求和取补）
│ │          │ └───── 数据
│ └──────────┴─────── 2 字符/字节的十六进制
└──────────────────── 起始冒号
```

LRC = `(0x100 - (sum(所有字节) & 0xFF)) & 0xFF`。ASCII 帧以 `CRLF` 结束。

## 4. 地址模型

Modbus 只有 4 张表，均为逻辑地址空间，与物理内存映射由设备厂商决定：

| 表 | 数据宽度 | 访问 | 协议地址（PDU，0 基） | 传统文档引用号（1 基） | 常见写法 |
|---|---|---|---|---|---|
| 线圈 Coils | 1 bit | 读/写 | 0x0000–0xFFFF | 00001–09999 | 0x |
| 离散输入 Discrete Inputs | 1 bit | 只读 | 0x0000–0xFFFF | 10001–19999 | 1x |
| 输入寄存器 Input Registers | 16 bit | 只读 | 0x0000–0xFFFF | 30001–39999 | 3x |
| 保持寄存器 Holding Registers | 16 bit | 读/写 | 0x0000–0xFFFF | 40001–49999 | 4x |

> **关键偏差（工程故障高发点）**：协议线上地址 **0 基**，人读文档地址 **1 基**。
> 文档中的“40001”在线上的起始地址是 `0x0000`；二者相差 1，是组态错位与“读错表”的常见根因，
> 也是攻击者判断设备厂商实现偏差的指纹之一（越界响应 vs 异常码 0x02）。
> 4 张表 **地址空间相互重叠**，靠功能码区分，而非靠地址区分。

## 5. 功能码表

### 5.1 公共功能码（Public Function Codes，规范定义）

| 码 | 名称 | 作用对象 | 数据长度/范围 | 备注 |
|---|---|---|---|---|
| 0x01 | Read Coils | 线圈 | 1–2000 位 | 批量读，响应按位打包 |
| 0x02 | Read Discrete Inputs | 离散输入 | 1–2000 位 | 只读 |
| 0x03 | Read Holding Registers | 保持寄存器 | 1–125 个寄存器 | 最常用，读实时量/定值 |
| 0x04 | Read Input Registers | 输入寄存器 | 1–125 个寄存器 | 只读，遥测常用 |
| 0x05 | Write Single Coil | 线圈 | 1 位 | 值仅 `0xFF00`(ON) / `0x0000`(OFF) |
| 0x06 | Write Single Register | 保持寄存器 | 1 个寄存器 | 单点遥控/定值下发 |
| 0x07 | Read Exception Status | — | — | 仅串行链路 |
| 0x08 | Diagnostics | — | 子功能 0x0000–0x0012 | 仅串行链路；含回环、计数器、强制只听 |
| 0x0B | Get Comm Event Counter | — | — | 仅串行链路 |
| 0x0C | Get Comm Event Log | — | — | 仅串行链路 |
| 0x0F | Write Multiple Coils | 线圈 | 1–1968 位 | 批量置位 |
| 0x10 | Write Multiple Registers | 保持寄存器 | 1–123 个寄存器 | 批量定值/批量遥控 |
| 0x11 | Report Server ID | — | — | 仅串行链路；设备指纹面 |
| 0x14 | Read File Record | 文件记录 | — | 少见；文件型数据（录波/事件） |
| 0x15 | Write File Record | 文件记录 | — | 少见；写入面 |
| 0x16 | Mask Write Register | 保持寄存器 | AND/OR 掩码 | 位级改写 |
| 0x17 | Read/Write Multiple Registers | 保持寄存器 | 读 1–125 / 写 1–121 | 单事务原子读写 |
| 0x18 | Read FIFO Queue | FIFO | — | 少见 |
| 0x2B | Encapsulated Interface Transport (MEI) | — | MEI 类型见下 | 设备标识/对象字典 |
| 0x5A | （厂商私有） | — | — | 部分设备用于固件/私有命令，常被误认“未知功能码” |

MEI（0x2B）子类型：

| MEI 类型 | 名称 | 说明 |
|---|---|---|
| 0x0D | CANopen General Reference Request | 读 CANopen 对象 |
| 0x0E | Read Device Identification | 读码 01=基本 / 02=常规 / 03=扩展 / 04=指定对象 |
| 0x0F | Read File Record（封装） | — |

Read Device Identification 对象 ID：`0x00` VendorName、`0x01` ProductCode、`0x02` MajorMinorRevision、
`0x03` VendorURL、`0x04` ProductName、`0x05` ModelName、`0x06` UserApplicationName。

厂商私有功能码范围：`0x41`–`0x48`、`0x64`–`0x6E`、`0x5A` 等，实现各异。

### 5.2 异常码（异常响应 = 功能码 | 0x80 + 1 字节异常码）

| 码 | 名称 | 触发条件 |
|---|---|---|
| 0x01 | Illegal Function | 功能码不支持（或在当前模式下不可用） |
| 0x02 | Illegal Data Address | 地址/数量越界 |
| 0x03 | Illegal Data Value | 数据域取值非法（如数量超上限） |
| 0x04 | Server Device Failure | 服务端执行未恢复错误 |
| 0x05 | Acknowledge | 已接受，需较长时间处理 |
| 0x06 | Server Device Busy | 正在处理长任务，稍后重试 |
| 0x07 | Negative Acknowledge | 无法执行该功能 |
| 0x08 | Memory Parity Error | 存储校验错 |
| 0x0A | Gateway Path Unavailable | 网关下游不可达（网关未配置该单元） |
| 0x0B | Gateway Target Device Failed To Respond | 网关下游无响应（超时） |

`0x0A`/`0x0B` 对探测有价值：前者证明是网关且目标未配置，后者证明下游设备存在但不响应。

### 5.3 常用 PDU 编码细节

| 功能码 | 请求 PDU | 响应 PDU |
|---|---|---|
| 0x01/0x02 | FC + 起始(2) + 数量(2) | FC + 字节数(1) + 位打包数据 |
| 0x03/0x04 | FC + 起始(2) + 数量(2) | FC + 字节数(1) + 寄存器值(2×N) |
| 0x05 | FC + 地址(2) + 值(2, `FF00`/`0000`) | 请求回显 |
| 0x06 | FC + 地址(2) + 值(2) | 请求回显 |
| 0x0F | FC + 起始(2) + 数量(2) + 字节数(1) + 位数据 | FC + 起始(2) + 数量(2) |
| 0x10 | FC + 起始(2) + 数量(2) + 字节数(1) + 值 | FC + 起始(2) + 数量(2) |
| 0x08 | FC + 子功能(2) + 数据(2) | 回显或统计值 |

Diagnostics 子功能要点：`0x0000` Return Query Data（回环，可用于探测夹层/网关改写）、
`0x0001` Restart Communications Option、`0x0004` **Force Listen Only Mode**（设备进入只听，不再应答）、
`0x000A` Clear Counters、`0x000B`–`0x0012` 各类计数器。

## 6. 已知安全弱点

### 6.1 协议设计层面（无法靠配置消除）

| 弱点 | 说明 | 影响 |
|---|---|---|
| 无认证 | 任何能连到 502/tcp 的主机即为“主站” | 未授权读写 |
| 无授权分级 | 读遥测与写遥控用同一通道、同一凭据（无凭据） | 只读账户不可能存在 |
| 无加密/无完整性 | 明文 PDU，无 MAC/签名 | 可嗅探、可篡改、可重放 |
| 无会话/无序号 | 无 nonce、无单调序号、无超时状态机 | 重放与并发注入不可检测 |
| 无速率限制 | 无背压约定 | 高频请求即 DoS |
| 广播语义 | 地址 0x00 广播写，无需确认 | 一次性影响全部下游从站 |

### 6.2 功能码滥用面

| 功能码 | 滥用方式 | 电力语境后果 |
|---|---|---|
| 0x05 / 0x0F（线圈） | 直接写遥控出口/合分闸线圈、闭锁/复归线圈 | 开关误动/拒动、保护压板投退被改 |
| 0x06 / 0x10 / 0x16（保持寄存器） | 改定值、改死区、改变比、改遥控选择 | 保护定值漂移、计量偏差、遥测失真 |
| 0x03 / 0x04 | 全表扫描读（0–0xFFFF 全地址空间批量读） | 一次会话即得完整过程画像（T0861/T0877） |
| 0x08 子功能 0x0004 | Force Listen Only Mode | 设备停止应答 = 失去监视与控制（T0814） |
| 0x08 子功能 0x0001 | Restart Communications | 通信复位/计数器清空，掩盖痕迹 |
| 0x11 / 0x2B | Report Server ID / Read Device Identification | 厂商、型号、固件版本指纹 |
| 0x14 / 0x15 | 文件记录读写 | 事件/录波文件外泄；写入面视实现而定 |
| 0x5A 及私有码 | 厂商调试/固件通道 | 常用于“协议外”能力，检测困难 |

### 6.3 封装与网关特有面

- **单元标识符混淆**：网关把 Unit ID 映射到下游串行从站。同一 IP 上扫 Unit ID 0–255 等于枚举
  网关后全部串行设备；不同 Unit ID 的响应差异可用于拓扑推断。
- **MBAP 长度/协议字段畸变**：Protocol ID ≠ 0、Length 与实际不符、超长 PDU，不同栈处理不一致，
  是 DPI/IDS 与设备行为差异（“协议解析分歧”）的经典来源。
- **TCP 分段规避**：部分 IDS 不做完整 TCP 重组，PDU 跨段切分可绕过基于单包的特征匹配。
- **私有变体**：厂商在 PDU 中追加私有头/尾；同一功能码语义不同，导致“读到的值看似正常但含义不同”。
- **串行链路劫持**：RS-485 总线为共享介质，可挂接监听或伪造主站；无任何端口安全。

### 6.4 电力场景落地（客观描述攻击面，不含操作步骤）

- **配网自动化**：DTU/FTU/TTU 经无线/光纤回传，前置机以 Modbus 汇总。线圈写 = 柱上开关分合。
- **电能量计量**：关口表/采集终端以 Modbus 输出电能量与瞬时量，保持寄存器改写直接影响结算数据。
- **辅控与站用电**：水泵、风机、空调、消防联动 PLC 多为 Modbus，是进入站内网络的低阻力面。
- **新能源场站**：光伏逆变器、储能 PCS 的功率设定点/启停常以 Modbus 暴露，直接对应出力控制。
- **网关横移**：Modbus↔EtherNet/IP、Modbus↔IEC 104、Modbus↔BACnet 网关是跨域跳板（其自身管理口
  与配置面常为 Web/SNMP 弱口令）。

## 7. 检测与指纹要点

| 手段 | 值/要点 |
|---|---|
| 端口 | 502/tcp（显式）；502/udp 少见实现；串行经网关映射 |
| nmap | `modbus-discover.nse`（设备识别/枚举，支持 Unit ID 遍历）；`modicon-info.nse`（施耐德专有信息） |
| Wireshark | 显示过滤器 `mbtcp`；解析器 `packet-mbtcp.c` |
| Scapy | `scapy.contrib.modbus`（`ModbusADURequest` 等） |
| 抓包样例 | ICS-pcap 仓库 `MODBUS/` 目录；S4x15 ICS Village PCAP |
| 检测基线（正常态） | 主站数量稳定且可枚举；Unit ID 集合固定；轮询周期固定；**写类功能码（05/06/0F/10/15/16）只应来自前置机/工程师站** |
| 高危信号 | 任意非授权源出现写类功能码；全地址空间批量扫描式读（0x03/0x04 高频递增）；0x08 诊断调用；0x2B 指纹枚举；广播地址（0x00/0xFF）写；单位时间请求数远超轮询周期 |
