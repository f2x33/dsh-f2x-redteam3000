## 1. 体系构成与端口

| 组成 | 标准 | 承载 | 标识 |
|---|---|---|---|
| 信息模型（LD/LN/DO/DA、CDC、FC） | IEC 61850-7-3/-7-4 | — | 命名空间分层 |
| 抽象通信服务接口 ACSI | IEC 61850-7-2 | — | 服务语义定义 |
| **MMS 映射**（客户端/服务器：控制、报告、文件） | IEC 61850-8-1 | ISO-on-TCP，**102/tcp** | MMS over TPKT/COTP |
| **GOOSE**（快速跳闸/联锁，发布订阅） | IEC 61850-8-1 | **以太网二层组播** | **EtherType `0x88B8`** |
| **SV 采样值** | IEC 61850-9-2（及 9-2LE、60044-8/FT3） | **以太网二层组播** | **EtherType `0x88BA`** |
| **GSSE**（旧式 GOOSE，UCA 遗产） | IEC 61850-8-1 附录 | 二层组播 | EtherType `0x88B9` |
| SCL 配置语言族 | IEC 61850-6 | XML 文件 | SSD/SCD/ICD/CID/IID/SED |
| 时间同步 | IEC 61850-9-3 / IEEE 1588 | 二层/三层 | PTP |

> 102/tcp 是**多协议共用端口**（S7comm、ICCP/TASE.2、MMS 均在此）。
> 仅凭端口无法判定协议，必须看 COTP 之后的载荷：MMS 以 OSI 会话/表示层（`0x0d 0x0d ...`）开头，
> S7 以 `0x32` 直接开头。这是分诊与误报控制的关键。

二层组播地址段：

| 用途 | 目的 MAC 范围 | 说明 |
|---|---|---|
| GOOSE | `01-0C-CD-01-00-00` – `01-0C-CD-01-01-FF` | 每 GOOSE 控制块一个组播地址 |
| GSSE | `01-0C-CD-02-00-00` – `01-0C-CD-02-01-FF` | 旧式 |
| SV | `01-0C-CD-04-00-00` – `01-0C-CD-04-01-FF` | 合并单元 → 保护/测控 |
| 时间同步 | `01-0C-CD-01-81-00` 等 | PTP profile 相关 |

## 2. 信息模型（LD / LN / DO / DA）

### 2.1 层次

```
Server（IED）
└── Logical Device (LD)            例：TEMPLATE / PROT / CTRL / MU01
    └── Logical Node (LN)          例：LLN0 / LPHD1 / XCBR1 / PTOC1 / MMXU1
        └── Data Object (DO)       例：Pos / A / Hz / Str / Op
            └── Data Attribute (DA) 例：stVal / q / t / mag / units
```

完整引用路径（对象引用）两种写法：

- 点号路径（MDS/DA 层）：`TEMPLATE/XCBR1.Pos.stVal`
- **FCDA / 数据集引用（带功能约束）**：`TEMPLATE/XCBR1$ST$Pos$stVal`
  （`$` 依次分隔 LD、LN、FC、DO、DA）

### 2.2 功能约束 FC（Functional Constraint）

| FC | 含义 | FC | 含义 |
|---|---|---|---|
| ST | 状态信息 Status | CF | 配置 Configuration |
| MX | 测量值 Measurands | DC | 描述 Description |
| CO | 控制 Control | SG | 定值组 Setting Group |
| SP | 设定值 Setpoint | SE | 可编辑定值组 |
| SV | 取代值 Substitution | EX | 扩展 Extended |
| BL | 闭锁 Blocking | SR | 服务响应 Service Response |
| RP | 非缓存报告 | BR | 缓存报告 |
| GO | GOOSE 控制 | GS | GSSE 控制 |
| MS | 多播采样值 | US | 单播采样值 |

### 2.3 逻辑节点首字母分组（IEC 61850-7-4）

| 首字母 | 域 | 典型 LN |
|---|---|---|
| L | 系统逻辑节点 | **LLN0**（逻辑节点零，LD 级）、**LPHD**（物理装置） |
| P | 保护 | PDIS（距离）、PTOC（过流）、PIOC（速断）、PDIF（差动）、PTOV/PTUV（过/欠压）、PFRC（频率）、PTRC（跳闸出口）、RREC（重合闸） |
| R | 保护相关 | RDRE（录波）、RBRF（断路器失灵）、RSYN（同期）、RADR（扰动记录） |
| C | 控制 | **CSWI**（开关控制器）、CILO（联锁）、CCGR（冷却组） |
| X | 开关设备 | **XCBR**（断路器）、**XSWI**（隔离开关/刀闸） |
| M | 测量 | **MMXU**（三相测量）、MMTR（电能计量）、MSQI（序分量）、MHAI（谐波） |
| T | 互感器 | TCTR（电流互感器）、TVTR（电压互感器） |
| Y | 电力变压器 | YPTR、YEFN、YLTC（分接头） |
| Z | 其它一次设备 | ZMOT（电机）、ZGEN（发电机）、ZSAR（弧光） |
| G | 通用 | GGIO（通用 IO） |
| S | 传感器 | STMP（温度）、SPTR（压力） |
| I | 接口/归档 | IHMI、ITCI、IARC |
| A | 自动控制 | ATCC（自动调压） |

### 2.4 公共数据类 CDC（Common Data Class，IEC 61850-7-3）

| CDC | 含义 | 典型 DA | 电力语境 |
|---|---|---|---|
| SPS | 单点状态 | stVal, q, t | 压板/告警接点 |
| DPS | 双点状态 | stVal（00/01/10/11）, q, t | 开关位置（`01`=分、`10`=合、`00`/`11`=中间/无效） |
| INS | 整数状态 | stVal, q, t | 档位、计数 |
| ENS | 枚举状态 | stVal, q, t | 模式/动作原因 |
| ACT | 保护动作 | general, phsA/B/C, q, t | 保护动作指示 |
| ACD | 方向/启动 | general, dirGeneral, q, t | 方向判别 |
| SEC | 安全违例 | cnt, sev, t | 安全事件 |
| BCR | 二进制计数器 | actVal, frVal, q, t | 动作次数 |
| MV | 测量值 | mag.f, units, q, t | 电流/电压/功率/频率 |
| CMV | 复数测量值 | cVal, units, q, t | 相量 |
| SAV | 采样值 | instMag, q, t | 采样 |
| WYE | 三相系统 | phsA/B/C, neut, res | 三相量组合 |
| DEL | 三相量（相间） | phsAB/BC/CA | 线电压/功率 |
| SEQ | 序分量 | c1, c2, c3 | 正/负/零序 |
| APC | 模拟定值 | setMag, operTm | 定值 |
| SPG / ING / ASG | 定值 | setVal | 定值组 |
| DPL | 铭牌 | vendor, serNum, model | **设备指纹** |
| LPL | 逻辑节点铭牌 | ldNs, lnNs | 版本信息 |
| TCS | 可控安全 | — | — |
| ORG | 动作原因 | — | — |
| HMV | 谐波测量 | — | 谐波 |

`q`（Quality，13 位位串）是电力语境的关键字段：validity（good/invalid/reserved/test/questionable）、
overflow、outOfRange、badReference、oscillatory、failure、oldData、inconsistent、inaccurate 等位。
数据操纵攻击若只改幅值而不同步改 `q`/`t`，是检测的直接抓手。

## 3. MMS（ISO 9506 over ISO-on-TCP，102/tcp）

### 3.1 封装

```
TCP 102
└── TPKT (4B: 03 00 len2)
    └── COTP (ISO 8073：CR/CC 建链 + DT 数据传输)
        └── OSI Session / Presentation（MMS 为空实现：0x0d 0x0d 0x00 0x00 ...）
            └── MMS PDU (ASN.1 BER 编码)
```

MMS PDU 类型（BER 标签）：

| 标签 | PDU | 用途 |
|---|---|---|
| `0xa0` | confirmed-requestPDU | 客户端请求（绝大多数 ACSI 服务的载体） |
| `0xa1` | confirmed-responsePDU | 成功响应 |
| `0xa2` | confirmed-errorPDU | 错误响应 |
| `0xa3` | unconfirmedPDU | 服务器主动发送（**报告/InformationReport**） |
| `0xa4` / `0xa5` / `0xa6` | reject / cancel-req / cancel-resp | 拒绝/取消 |
| `0xa8` / `0xa9` | initiate-requestPDU / initiate-responsePDU | 关联建立（含协商参数） |
| `0x8b` / `0x8c` | conclude-requestPDU / conclude-responsePDU | 关联释放 |
| `0x0b` / `0x0c` | （a-abort） | 异常中止 |

### 3.2 常用 MMS 服务标签（confirmed-request 内）

| 标签 | 服务 | ACSI 对应 |
|---|---|---|
| `0xa1` | GetNameList | GetServerDirectory / GetLogicalDeviceDirectory / GetLogicalNodeDirectory / GetDataDirectory |
| `0xa2` | Identify | （厂商/版本信息） |
| `0xa4` | Read | GetDataValues / GetBRCBValues / GetURCBValues |
| `0xa5` | Write | SetDataValues / SetBRCBValues / **控制 operate** |
| `0xa6` | GetVariableAccessAttributes | GetDataDefinition / GetDataDirectory |
| `0xab` | DefineNamedVariableList | **CreateDataSet** |
| `0xac` | GetNamedVariableListAttributes | GetDataSetDirectory |
| `0xad` | DeleteNamedVariableList | DeleteDataSet |
| `bf 48` | fileOpen | FileOpen（录波/COMTRADE、SCL 外带） |
| `bf 49` | fileRead | FileRead |
| `bf 4a` | fileClose | FileClose |
| `bf 4b` | fileRename | — |
| `bf 4c` | fileDelete | FileDelete |
| `bf 4d` | fileDirectory | FileDirectory（目录枚举 = 文件发现） |

> `0xbf xx` 为 BER 长标签形式（标签号 ≥ 31）。`0xa0`（unconfirmed 内的 informationReport）
> 与 `0xa0`（PDU 类型）标签数值相同但**嵌套位置不同**，解析时必须按层级判定。

### 3.3 报告与数据集机制

1. 客户端 `DefineNamedVariableList`（`0xab`）建立数据集，成员为 FCDA 引用（如 `PROT/XCBR1$ST$Pos$stVal`）。
2. `Write` 到 BRCB/URCB 的 `RptEna`、`TrgOps`、`OptFlds`、`DatSet` 等属性使能报告。
3. 数据变化或周期到达时，服务器以 unconfirmed `InformationReport`（`0xa3` → `0xa0`）主动推送。
4. 报告内容 = 数据集成员的值序列（顺序由数据集定义决定）——**该顺序是解析业务含义的前提**。

### 3.4 控制模型（Operate）

控制对象（如 `CSWI1.Pos`）的 `Oper` 结构是**直接操作一次设备的通道**：

| 结构 | 方向 | 关键成员 |
|---|---|---|
| Oper | 客户端写 | ctlVal（控制值）、origin（来源）、ctlNum（控制序号）、T（时间）、Test、Check |
| SBOw | 客户端写 | 带选择的操作（Select-Before-Operate） |
| Cancel | 客户端写 | 取消 |
| Oper / SBOw（响应） | 服务器返回 | 上次操作的回显 |

`ctlVal` 对 DPS 型 `Pos` 的取值：`01` = 分（open/trip）、`10` = 合（close）。
`origin` 字段用于标识操作来源（站控层/远方/就地），是事后溯源的关键证据字段。

## 4. GOOSE（IEC 61850-8-1）

### 4.1 帧结构

```
+---------------------------+------------------------------------------+
| 目的 MAC (6)               | 01-0C-CD-01-xx-xx（GOOSE 组播段）          |
| 源 MAC (6)                 | IED 网口 MAC                              |
| 802.1Q 标签 (4)             | TPID=0x8100, TCI: PCP 常见 4, VID 按工程    |
| EtherType (2)              | 0x88B8                                    |
+---------------------------+------------------------------------------+
| APPID (2)                 | 应用标识，发布方与订阅方约定                  |
| Length (2)                | = 4（两个 Reserved）+ GOOSE PDU 长度         |
| Reserved1 (2) = 0x0000    |                                           |
| Reserved2 (2) = 0x0000    |                                           |
+---------------------------+------------------------------------------+
| GOOSE PDU（ASN.1 BER，外层 SEQUENCE 标签通常省略）                       |
+--------------------------------------------------------------------------+
```

GOOSE PDU 字段与 BER 上下文标签：

| 标签 | 字段 | 类型 | 说明 |
|---|---|---|---|
| `0x80` | gocbRef | VisibleString | 控制块引用，`LD/LN$GO$gcbName` |
| `0x81` | timeAllowedToLive | Integer | 接收方等待下一帧的最长时间（ms） |
| `0x82` | datSet | VisibleString | 数据集引用，`LD/LN$dsName` |
| `0x83` | goID | VisibleString | 可选，工程标识 |
| `0x84` | t | UtcTime (8B) | 状态变化时刻 |
| `0x85` | stNum | Integer | **状态号**：数据每次变化 +1 |
| `0x86` | sqNum | Integer | **序号**：每次重传 +1，stNum 变化时归 0 |
| `0x87` | test | Boolean | 测试标志 |
| `0x88` | confRev | Integer | 配置版本号 |
| `0x89` | ndsCom | Boolean | 需配置标志 |
| `0x8a` | numDatSetEntries | Integer | 数据集成员数 |
| `0xab` | allData | 构造 | 数据集成员值序列（**顺序 = 数据集定义顺序**） |

`allData` 成员的数据类型标签（Wireshark `packet-goose.c` 归类）：

| 标签 | 类型 |
|---|---|
| `0x83` | boolean |
| `0x84` | bit-string（含 Quality 位串） |
| `0x85` | integer |
| `0x86` | unsigned |
| `0x87` | floating-point |
| `0x89` | octet-string |
| `0x8a` | visible-string |
| `0x91` | utc-time |
| `0xa1` | array（构造） |
| `0xab` | structure（构造） |

### 4.2 构造示例帧（字段自洽，长度已校验；非现场抓包）

单成员数据集（1 个布尔量 = TRUE），APPID=1：

```
01 0c cd 01 00 01                          # 目的 MAC：GOOSE 组播
00 21 c1 12 34 56                          # 源 MAC
81 00 80 00                                # 802.1Q：PCP=4, DEI=0, VID=0
88 b8                                      # EtherType = GOOSE
00 01                                      # APPID = 1
00 60                                      # Length = 96 = 4 + 92(PDU)
00 00 00 00                                # Reserved1 = Reserved2 = 0
80 16 54 45 4d 50 4c 41 54 45 2f 4c 4c 4e 30 24 47 4f 24 67 63 62 30 31
       └─ "TEMPLATE/LLN0$GO$gcb01"（22 字节）gocbRef
81 02 03 e8                                # timeAllowedToLive = 1000 ms（BER 长度=2：0x03E8）
82 16 54 45 4d 50 4c 41 54 45 2f 4c 4c 4e 30 24 64 73 47 4f 4f 53 45 31
       └─ "TEMPLATE/LLN0$dsGOOSE1"（22 字节）datSet
83 05 67 63 62 30 31                       # goID = "gcb01"
84 08 69 55 b9 00 00 00 00 00              # t：UtcTime = 秒(4, 大端 0x6955B900 = 2026-01-01T00:00:00Z) + 小数(3) + 质量(1)
85 01 2a                                   # stNum = 42
86 01 00                                   # sqNum = 0
87 01 00                                   # test = false
88 01 01                                   # confRev = 1
89 01 00                                   # ndsCom = false
8a 01 01                                   # numDatSetEntries = 1
ab 03 83 01 01                             # allData：[ boolean TRUE ]
```

### 4.3 重传与状态机（行为基线）

- **事件驱动**：数据集任一成员变化 → `stNum` +1、`sqNum` 归 0，并按
  T1（事件后最短重传间隔，毫秒级）→ T2 → T3 退避重传，直到回到 T0（稳定期心跳，工程常用 1–5 s）。
- `timeAllowedToLive` 一般约为心跳周期的 2 倍；订阅方超时未收到即判链路中断（GOOSE 断链告警/闭锁）。
- 订阅方接受规则（简化为工程共识）：`stNum` 更新 → 接受并刷新；`stNum` 相同则要求 `sqNum` 递增；
  仅当 `confRev`/`datSet`/`goID`/APPID 匹配订阅配置时才采信。
- **无认证、无签名、无序号随机化**：任何接入同一 VLAN 的主机都可发布 GOOSE，
  且可通过构造高 `stNum` + `sqNum=0` 的帧让订阅方认为“这是最新状态”。

### 4.4 GOOSE 已知弱点（对照参考数据集）

参考仓库 `IEC61850SecurityDataset` 以 4 母线 / 18 IED 变电站为对象，给出三类 GOOSE 攻击的
公开 trace 与手法（以下为其 README 的分类索引，不含操作步骤）：

| 类别 | 代号 | 手法（README 归纳） |
|---|---|---|
| 数据操纵 Data Manipulation | DM.1 | 修改合并单元上报的电流测量值（伪造幅值） |
| | DM.2 | 注入被篡改的断路器布尔状态 |
| | DM.3 | 重放此前有效的报文 |
| 报文抑制 Message Suppression | MS.1 | 注入 GOOSE 序号 sqNum |
| | MS.2 | 注入 GOOSE 状态号 stNum（含高 stNum + sqNum=0 使接收方接受陈旧/伪造状态） |
| 拒绝服务 DoS | DoS.1 | 泛滥伪造帧（README 记为两台 IED 各注入 5000 帧） |
| 组合攻击 Composite | — | 高 stNum 注入 + 断路器状态篡改（针对 CB-11） |

数据集还覆盖电力业务扰动（母线保护 BusbarProtection、断路器失灵 BreakFailure、低频减载
UnderFrequency）的**正常态** trace，可直接作为“业务基线 vs 攻击态”的差分素材；
`SCL/` 目录含 18 个 IID 文件，可用于还原 GOOSE 报文的载荷结构与数据集成员顺序。

## 5. SV 采样值（IEC 61850-9-2 / 9-2LE）

```
以太网头部（目的 MAC 01-0C-CD-04-xx-xx，EtherType 0x88BA）
├── APPID (2) / Length (2) / Reserved1 (2) / Reserved2 (2)   ← 与 GOOSE 相同的 8 字节头
└── savPdu
    ├── noASDU (1)
    └── Sequence of ASDU
        └── 每个 ASDU：svID, smpCnt(2), confRev(4), refrTm(8, 可选),
                       smpSynch(1), smpMod/smpRate(视版本),
                       Sequence of Data（每个成员 8 字节：4 字节瞬时值 + 4 字节 Quality）
```

| 项 | 值 |
|---|---|
| 发送速率 | 9-2LE：保护用 **80 点/周波**（50 Hz → 4000 帧/s）；电能质量用 256 点/周波（12800 帧/s） |
| 方向 | 合并单元（MU）→ 保护/测控/计量 IED（单向） |
| 带宽 | 极高；工程上需专用 VLAN/端口镜像谨慎处理 |
| 已知弱点 | 与 GOOSE 相同：**无认证无签名**（IEC 62351-6 定义了签名但极少部署）；伪造采样值可直接误导保护算法（对应上表 DM.1）；风暴式注入即 DoS |
| 检测抓手 | `smpCnt` 连续性/回绕、`smpSynch`、`confRev` 与 SCD 是否一致、单帧速率与周波基准的偏差 |

## 6. SCL 文件族（IEC 61850-6）

| 扩展名 | 名称 | 内容 | 攻防价值 |
|---|---|---|---|
| **SSD** | System Specification Description | 一次系统单线图 + 变电站功能定义（Substation/Section） | 拓扑与间隔划分 |
| **SCD** | Substation Configuration Description | **全站唯一完整配置**：通信参数、IED、数据集、GOOSE 连线、Report 控制块 | 最高价值：全站资产/APPID/组播地址/数据集成员顺序/GOOSE 订阅关系 |
| **ICD** | IED Capability Description | 装置能力描述（模板） | 型号能力、逻辑节点清单 |
| **CID** | Configured IED Description | 下装到单台 IED 的实例化配置 | 单装置配置与数据集 |
| **IID** | Instantiated IED Description | 实例化 IED 描述（工程中间态，参考数据集即用 IID 描述 18 台 IED） | 数据集成员结构、DA 属性 |
| **SED** | System Exchange Description | 工程间交换描述 | 跨工程边界信息 |

SCD/CID 是 XML 明文，通常由工程/厂商在站内系统与**工程师站、后台服务器、远动网关**上保存；
其泄露等于全站通信地图与数据语义的泄露（对应 T0811 / T0882）。

## 7. 已知安全弱点汇总

| 面 | 弱点 | 说明 | 电力后果 |
|---|---|---|---|
| GOOSE | 无认证/无完整性 | 二层组播，任何同 VLAN 主机可发布 | 伪造跳闸/闭锁/位置（误动、拒动） |
| GOOSE | 无重放保护（无 nonce/时间窗） | stNum/sqNum 可被构造 | 陈旧状态被接受；断路器状态被回滚 |
| GOOSE | 序号可被抢占 | 高 stNum + sqNum=0 使订阅方接受 | 真实报文被“抑制”（MS 类） |
| GOOSE | 无速率限制 | 泛洪即 DoS | 保护跳闸报文丢失 = 保护失效 |
| GOOSE | 依赖 VLAN/端口隔离 | 配置错误即全网可注入 | 单点接入影响全站保护 |
| SV | 同 GOOSE + 采样值可直接伪造 | 无签名 | 保护误判（差动/距离） |
| MMS | 默认无认证 | 关联建立无需口令 | 未授权读全模型、写控制对象 |
| MMS | 控制对象 `Oper` 可直接写 | Operate 通道一次设备操作 | 遥控分合闸（T1692.001） |
| MMS | 文件服务 | FileOpen/Read/Directory | 外带录波（COMTRADE）、SCD、定值（T0893/T0882） |
| MMS | GetNameList/GetVariableAccessAttributes | 免认证全模型枚举 | 完整资产与数据语义画像（T0861/T0848 前置） |
| 时间 | 时间源可被欺骗 | 依赖 PTP/SNTP | 时间戳失真 → 事件排序与保护配合错乱 |
| 工程面 | SCD/CID/工程文件 | 明文 XML、可写 | 篡改后随下装生效 = 持久化（T0889/T0873） |
| 标准层 | IEC 62351-6 签名未部署 | 保护动作毫秒级预算与签名开销冲突 | 防护面基本空白 |

IEC 62351 系列定位（作为对照基准）：

| 分册 | 内容 |
|---|---|
| 62351-3 | TCP/IP 协议集的 TLS（含 MMS 承载） |
| 62351-4 | MMS 端到端安全（TLS + 应用层认证） |
| 62351-5 | DNP3 安全认证（见 `dnp3.md`） |
| 62351-6 | **GOOSE / SV 的数字签名**（RSA/ECDSA） |
| 62351-8 | 基于角色的访问控制（RBAC） |
| 62351-9 | 密钥管理 |
| 62351-90-1/-2/-3 | 电力系统角色与 RBAC 落地指南 |

现实部署率：-3/-4 少数新建站部署；**-6 在保护通道上基本未部署**。

## 8. 检测与指纹要点

| 手段 | 值/要点 |
|---|---|
| nmap | `iec61850-mms.nse`（MMS 关联 + 模型读取） |
| Wireshark | `goose`、`sv`、`mms`、`cotp` 过滤器；解析器 `packet-goose.c`、`packet-sv.c` |
| 库/工具 | `libiec61850`（开源实现，可用于自建验证环境与解析） |
| 正常态基线 | GOOSE 的 (APPID, gocbRef, datSet) 三元组集合固定；`confRev` 固定；心跳周期与重传模式符合 T0/T1；`stNum` 单调、`sqNum` 在 stNum 内递增 |
| 高危信号 | 同一 gocbRef 出现**两个源 MAC**；`stNum` 跳变异常（如 +9999）；`sqNum` 倒序或非 0 的 stNum 首次出现；`confRev` 变化；GOOSE/SV 帧速率远超周波基准（泛洪）；`t` 与接收时间显著偏离；MMS 侧非授权源出现 Write/DefineNamedVariableList/fileOpen；`test=1` 帧出现在生产通道 |
| 交叉校验 | 用 SCD/ CID 与实网 GOOSE 订阅关系比对（数据集成员顺序、APPID、组播地址一致性），不一致即为可疑配置篡改 |
