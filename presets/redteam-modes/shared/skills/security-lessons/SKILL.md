# 通用作战经验（跨目标可迁移）

> **本技能的边界**：只放**方法/判断层**——跨目标、跨镜像、跨年份都成立的规则。
> **不放**具体端口、路径、凭据、某平台架构、某靶场约定、某工具是否安装。
> 那些属**环境事实层**，必须单独存放并标注「仅本部署生效」（见文末「分层纪律」）。
> 一旦把事实当方法用，就会产生自信的错误结论——这是本技能存在的首要原因。

## 一、认知先验（开工即用）

1. **「声称安全」是负面信号，不是正面信号。** 目标自称"已加固 / 只开放 X 功能 / 只有管理员能访问"时，
   先验应设为：**控制多半只存在于展示层，真正的缺陷是服务端缺失校验**。按寻找「被隐藏的功能」而非
   「被保护的功能」来分配预算。
2. **提示/文档/UI 描述的是意图，不是实现。** 需求文档、接口说明、页面文案、UI 置灰项都只说明
   "设计者想让它怎样"，不说明"服务端实际怎么校验"。**必须去找实现与意图的差**。
3. **能读源码就读源码，这是最高性价比动作。** 泄露的源码、SDK 页、source map、`.git`、备份文件、
   反编译产物，能一枪打掉全部试错成本。读到源码后，结论应从"疑似"直接升到"确定"。
4. **发现 ≠ 真实存在；发现 + 验证 = 真实有效。** 证据分三档：`confirmed`（可复现/原始报文）、
   `partial`（工具输出/间接）、`unknown`（未决）。`confirmed` 只在有可复现命令或外部权威回执时给。

## 二、攻击性价比序（按顺序做，不要跳）

1. **读代码/读客户端**：JS（内联+外链）、注释、source map、`.git`、备份、SDK/文档页 → 端点、密钥、sink。
2. **定终点，再找原语**：先明确"拿到什么算成功"（哪个数据/哪条权限/哪个文件），
   再集中火力找**那一个**原语（任意文件读 / 代码执行 / 认证绕过），不要四处浅试。
3. **认证优先「绕」**：解析歧义、逻辑缺陷、签名与校验缺口、状态可篡改；**爆破垫底**且必须限定预算
   （见 §四 反模式）。
4. **拿到原语后立刻收口**：不要在原语已足够时继续探索"更漂亮的链"——先交付，再扩展。

## 三、五类通用绕过（与语言、框架无关的**类别**）

判据不是"payload 长什么样"，而是"哪一层信任出了错"。遇到过滤器时按下表定位类别，再落到具体语法。

| 类别 | 本质 | 落地手法（举例方向，非穷举） |
|---|---|---|
| **编码层差** | 过滤器与解析器对同一字节流理解不同 | 多字节编码/字符集切换（UTF-16 等）、Unicode 归一化、八进制/十六进制转义、双写、大小写、百分号编解码层数 |
| **黑名单本质缺陷** | 黑名单永远枚举不全 | 换等价物（别名、反射/`getattr`、间接调用、动态拼名）、换语法（替代定界符、短标签）、拆词拼接 |
| **信任边界错位** | 校验发生在客户端或错误的层 | 直接重放请求绕前端校验；自造身份类 header；篡改客户端可改的状态对象 |
| **解析歧义** | 两处对同一输入的解析不一致 | 路径分隔符与规范化、绝对路径覆盖基准目录、双重编码（框架先解一层）、参数名规范化（大小写/点与下划线/方括号） |
| **序列化边界** | 可信数据与不可信数据混在同一容器 | 未签名/可篡改的客户端状态、元数据字段、对象注入、类型混淆 |

**使用纪律**：先**确认过滤器存在并定位它**（基线 vs 差分），再套类别；不要盲目喷射 payload。
每一次绕过都要留下"基线 / 差分 / marker"三件套，否则不算成立。

## 四、决策规则与反模式

**该做的**
- 卡点先**换面**（换入口、换 sink、换身份），不急着换目标。
- 放弃一条路径前必须**证伪**：留下"确认不可行 + 尝试清单 + 证据"，不要用"没打进去"代替"不可行"。
- 时间盒：单条路径设预算，到点即收，把结论落成 `partial/unknown` 继续推进。
- 卡住时的最后手段（按顺序）：读源码 → 看日志/报错 → 枚举被忽略的入口面（前缀扫描、非标准方法、
  低流量路径）→ 才考虑爆破。

**反模式（务必避免）**
- ❌ **把某次任务的环境事实当通杀规则**（最危险）。"上次 flag 在 X 路径"→ 换个目标就变成凭空假设。
- ❌ **把"某次爆破无效"推广为"爆破无用"**。爆破失效往往是**题目/目标的设计**结果，不是普遍规律；
  真实对抗中爆破常常有效。正确表述是"本例中爆破无收益"，而非"爆破没用"。
- ❌ **把提示当成漏洞位置**。提示常指向**主题**而非缺陷；也常存在诱饵（标注为"死路/无关"的功能其实
  真的是死路）。被暗示的路径死亡后要换面，不要耗尽预算。
- ❌ **无证据背书就采信结论**（包括工具自动判定与他人转述）。
- ❌ 把"我没打进去"写成"不可利用"。

## 五、分层纪律（本技能最重要的操作要求）

任何经验落盘前，先问：**这是方法，还是事实？**

- **方法层**（跨目标成立）→ 进本技能 / 对应 playbook，可全局复用。
- **事实层**（仅某部署/某目标/某时刻成立）→ 进战役记忆/黑板或工作区便签，**必须显式标注适用范围**，
  例如："仅本部署"、"仅本镜像"、"截至 <日期>"。

**判据**：一句话换个目标还成立吗？成立 → 方法；不成立 → 事实（即使它当时"验证过"）。
**验证过 ≠ 可迁移**——这一点最容易搞混。

## 六、证据与交付纪律

- 每条结论标注证据等级；报告只汇总原始结论，不改写、不加码。
- 复现命令 + 原始请求/响应必须落盘，使他人可独立重跑。
- 外部权威回执（平台判定/目标自身确认）优先于自报。
- 不删除、不破坏目标侧资产；我方残留清理同样走用户确认。

## 七、编排与时间盒（并发受限时的吞吐纪律）

**吞吐模型**：并发上限为 N 时，`makespan ≈ max(总任务时长 / N, 最长单任务时长)`。
一波的时长由**该波最慢者**决定，不是最快者——所以"把易题和难题混在一波"不会更快，
单题进度也不会因为同伴做完而加速。

**关键结论**：贪心派单（谁空给谁派下一题）通常已接近最优，
**真正的杠杆是压缩长尾任务的时长方差，而不是优化排期**。
实测一次 18 题 / 并发 3 的任务：16 题在 41 分钟内完成，最后 2 题又占了 25 分钟——
**11% 的任务吃掉约 29% 的槽位容量**；而实际 makespan 仅比理论最优差约 17%。

**纪律**
- **硬时间盒优先**：单任务到点（参考 12–15 分钟）强制要一次状态。
  有明确下一步 → 允许延期一次；没有 → 立即收 `NOT_FOUND` + 已确认结论，把槽位让给下一题。
  **长尾任务霸占槽位不释放，是并发受限场景下最大的浪费来源。**
- **槽位零空转**：任务一收口立即释放名额并启动下一题，不要让并发上限空着。
- **早给"最便宜的三条路"**：开工就告诉执行者先试最便宜的路径（读源码/绝对路径读/参数重放），
  避免它在昂贵路径上热身。
- **首批情报 turn-1 给全**：终点位置、环境能力与缺失项、目标身份校验方法、已知绕过形状——
  一次塞进任务描述，不要逐轮补（逐轮补＝每轮都在浪费墙钟）。
- **假设要早纠**：一旦发现自己的工作假设与执行者观测不符（例如预期 A 链、实际是 B 链），
  立刻给替代清单，不要让它继续沿错误假设烧时间。
